// Page 2 — Blockchain Fundamentals

Blockchain Explained

A distributed, immutable ledger technology that enables trustless, peer-to-peer transactions without intermediaries.

// Core Concept

What is a Blockchain?

A blockchain is a continuously growing list of records, called blocks, which are linked and secured using cryptography. Each block contains a cryptographic hash of the previous block, a timestamp, and transaction data.

The blockchain is managed by a peer-to-peer network collectively adhering to a protocol for inter-node communication and validating new blocks. Once recorded, data in a given block cannot be altered retroactively — this is what makes blockchain revolutionary.

Key Property: Immutability
Each block contains the hash of the previous block. If you change block #3, its hash changes, invalidating block #4, #5... all the way to the current block. This chain of cryptographic proof is what makes tampering computationally infeasible.
// Properties

Six Core Properties

🔗 Decentralization
No single point of control or failure. Nodes across the globe maintain copies.
🔒 Immutability
Recorded data cannot be changed without consensus of the network.
👁️ Transparency
All transactions are visible to participants; public chains are open to anyone.
⚡ Trustlessness
Smart contracts enforce rules automatically — no trust in a third party needed.

Smart Contracts

Self-executing code stored on the blockchain that automatically enforces the terms of an agreement — no lawyers, no intermediaries.

// Definition

Code is Law

Smart contracts are programs stored on a blockchain that run when predetermined conditions are met. They automate the execution of an agreement so all parties can be immediately certain of the outcome, without any intermediary's involvement or time loss.

Nick Szabo's Vision (1994)
Computer scientist Nick Szabo coined the term "smart contract" in 1994 — decades before blockchain made them feasible. He compared them to a vending machine: deposit coins, select product, machine executes automatically.

// EMS System Components

The EMS Chain

1. Public Access & Detection
Bystander recognition of emergency. Calling 911. Public CPR and AED programs that bridge response gaps.
2. Dispatch
Emergency Medical Dispatch (EMD). CAD systems. Priority dispatch with pre-arrival instructions to callers.
3. Field Response
BLS / ALS units responding. Scene assessment. Patient care. Continuous communication with medical direction.
4. Hospital Care
Definitive care. Trauma centers, cath labs, stroke centers. Pre-notification improves outcomes dramatically.

EMS Protocols

// START Triage System

Mass Casualty Triage

START (Simple Triage and Rapid Treatment) is used in mass casualty incidents to quickly classify patients by severity and survivability.

🟢
Minor (Green)
"Walking wounded." Delayed care. Can walk, follow commands. Minor injuries only. Can wait hours for treatment.
🟡
Delayed (Yellow)
Serious but stable. Breathing, pulse present. Can survive 4–6 hours without treatment. Second priority for care.
🔴
Immediate (Red)
Life-threatening but salvageable. Requires immediate intervention. Airway obstruction, severe hemorrhage, shock.
⚫
Expectant (Black)
Deceased or unsurvivable injuries. No respirations after airway repositioning, or injuries incompatible with survival.
// ABCDE Assessment

Primary Survey

A
Airway
Is airway patent? Head-tilt chin-lift, jaw thrust, suction, OPA/NPA.
B
Breathing
Rate, depth, effort. SpO2. BVM ventilation if inadequate. Seal open chest wounds.
C
Circulation
Pulse rate/quality. Control bleeding (tourniquets, hemostatics). IV/IO access.
D
Disability
GCS, pupils (PERRL), blood glucose. Signs of neuro compromise.
E
Exposure
Full body exam. Prevent hypothermia. Look for hidden injuries (back, axillae, groin).

// Blockchain + EMS Integration

Where Blockchain Meets Emergency Care

The intersection of blockchain and EMS represents a powerful new frontier. Patient care data stored on permissioned blockchain networks ensures privacy while enabling seamless sharing between EMS agencies, hospitals, and specialists.

Use Case: Universal Patient Record
A cardiac arrest patient's medical history, allergies, and advance directives stored on a blockchain are instantly accessible to any authorized paramedic with a smartphone — even in a different state or country.
Use Case: Drug Chain of Custody
Controlled substances (morphine, fentanyl) tracked via blockchain from pharmacy to ambulance to patient — eliminating diversion and ensuring audit trails for every dose.

Knowledge Glossary

Every key term across Blockchain, Technopedia, and EMS — defined clearly.

// Blockchain Terms

Blockchain & Web3

HashA fixed-length output produced by a cryptographic hash function (e.g., SHA-256). Deterministic: same input always produces same output. One-way: cannot reverse-engineer input from output.
NodeA participant in a blockchain network that maintains a copy of the ledger and validates transactions. Full nodes store the entire chain; light nodes store headers only.
MiningThe process of validating transactions and adding new blocks to a Proof-of-Work blockchain by solving computationally expensive cryptographic puzzles.
Crypto WalletSoftware storing private/public key pairs. Does not store coins — it stores keys that prove ownership of on-chain assets. Hot (online) vs Cold (hardware) wallets.
DAODecentralized Autonomous Organization. A community governed by smart contracts and token voting rather than traditional hierarchy or legal structure.
Layer 2Scaling solutions built on top of base blockchains. Optimistic rollups (Arbitrum) and ZK rollups (zkSync) process transactions off-chain and post proofs to L1.
Liquidity PoolSmart-contract-locked pairs of tokens enabling decentralized trading. Liquidity providers earn fees. AMMs (Automated Market Makers) like Uniswap use the x*y=k formula.
// EMS Terms

Emergency Medical Services

BLSBasic Life Support. Foundational emergency care including CPR, AED use, airway management with BVM, and hemorrhage control. Provided by EMT-Basics.
ALSAdvanced Life Support. Expanded care including IV/IO access, medication administration, intubation, cardiac monitoring, and 12-lead ECG. Provided by Paramedics.
TriageSystematic sorting of patients by injury severity and survivability. Maximizes lives saved with limited resources. START, SALT, and JUMPSTART are common systems.
GCSGlasgow Coma Scale. 3–15 neurological assessment scoring eye opening (1-4), verbal response (1-5), and motor response (1-6). <9 = severe TBI.
CapnographyContinuous monitoring of end-tidal CO2. Confirms endotracheal tube placement, monitors CPR quality, and detects return of spontaneous circulation (ROSC).
// Tech Terms

Technology

APIApplication Programming Interface. A defined set of methods allowing applications to communicate. REST APIs use HTTP verbs (GET, POST, PUT, DELETE) over standard protocols.
KubernetesOpen-source container orchestration system automating deployment, scaling, and management of containerized applications. Originally from Google; now CNCF.
Zero TrustSecurity model assuming no implicit trust for any user or device inside or outside the network perimeter. "Never trust, always verify." Uses MFA, least-privilege access.
